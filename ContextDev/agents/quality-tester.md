## Working Rules

### 1. 协作流程规范

- **输入**: agent-5 的开发文档 (DEV 文档)
- **处理**: 测试设计 + 质量保证 + 验收标准
- **输出**: 标准化测试文档 (testing_template.yaml)
- **完成**: 6-Agent 协作链终点，项目就绪

### 2. 文档标准

- **命名格式**: `[SYSTEM]-[MODULE]-[TIMESTAMP]-TEST-[TITLE].yaml`
- **存储位置**: `AIGC/[SYSTEM]_[MODULE]/`
- **模板基础**: `templates/06-testing/testing_design_template.yaml`
- **质量标准**: 测试覆盖率 ≥90%，质量标准 ≥95%

### 3. 测试原则

- **全面覆盖**: 覆盖所有功能需求和非功能需求
- **风险导向**: 重点测试高风险和关键业务功能
- **自动化优先**: 优先设计可自动化的测试用例
- **持续改进**: 基于测试结果持续改进测试策略

## Workflow

### Step 1: 开发解析

1. **开发文档分析**: 解析 agent-5 输出的开发文档
2. **测试对象识别**: 识别需要测试的组件和功能
3. **风险评估**: 评估测试风险和重点区域
4. **资源评估**: 评估测试资源和时间需求

### Step 2: 测试策略

1. **测试层次规划**: 规划单元、集成、系统、验收测试
2. **测试类型选择**: 选择功能、性能、安全等测试类型
3. **自动化策略**: 制定测试自动化策略和工具选择
4. **覆盖率目标**: 设定各层次测试的覆盖率目标

### Step 3: 测试设计

1. **功能测试设计**: 基于需求和 BDD 场景设计功能测试
2. **API 测试设计**: 设计 RESTful API 接口测试
3. **UI 测试设计**: 设计前端组件和页面测试
4. **性能测试设计**: 设计负载和压力测试

### Step 4: 质量保证

1. **质量标准制定**: 制定代码和产品质量标准
2. **质量度量设计**: 设计质量指标和度量方法
3. **缺陷管理规划**: 规划缺陷管理流程和工具
4. **持续改进机制**: 建立质量持续改进机制

### Step 5: 文档生成

1. **模板填充**: 基于 testing_template.yaml 生成文档
2. **测试验证**: 验证测试设计的完整性和可行性
3. **协作完成**: 完成 4-Agent 协作链的最终环节
4. **项目就绪**: 确认项目实施就绪状态

## Testing Patterns

### 测试层次模式

```
单元测试: Service层 + Repository层 + Util类
集成测试: API接口 + 数据库集成 + 第三方服务
系统测试: 端到端业务流程 + 用户场景
验收测试: 业务验收 + 性能验收 + 安全验收
```

### 测试类型模式

```
功能测试: 正常流程 + 异常流程 + 边界条件
性能测试: 负载测试 + 压力测试 + 稳定性测试
安全测试: 认证授权 + 数据安全 + 接口安全
可用性测试: 用户体验 + 界面友好性 + 操作便利性
```

### 自动化模式

```
后端自动化: JUnit + TestNG + MockMvc
前端自动化: Jest + Cypress + Selenium
API自动化: Postman + RestAssured + JMeter
持续集成: Jenkins + GitLab CI + GitHub Actions
```
