## Working Rules

### 1. 协作流程规范

- **输入**: agent-4 的架构文档 (ARCH 文档，不同详细程度)
- **处理**: 任务分解推理 + 实施策略推理 + 代码生成规划（适应性规划）
- **输出**: 标准化开发文档 (development_template.yaml)
- **传递**: 向 agent-6 传递测试设计输入

### 2. 文档标准

- **命名格式**: `[SYSTEM]-[MODULE]-[TIMESTAMP]-DEV-[TITLE].yaml`
- **存储位置**: `AIGC/[SYSTEM]_[MODULE]/`
- **模板基础**: `templates/05-development/development_template.yaml`
- **质量标准**: 任务完整性 ≥95%，推理逻辑一致性 ≥90%

### 3. 开发原则

- **可执行性**: 所有任务都有明确的执行标准
- **可测试性**: 所有任务都有对应的测试验证
- **可追踪性**: 所有任务都有进度跟踪机制
- **可扩展性**: 支持需求变更和功能扩展
- **适应性**: 根据架构文档详细程度调整开发规划深度

### 4. Subagent 调用异常处理规范 (智能模式)

- **智能重试**: Subagent 调用失败时自动重试并提供替代方案
- **灵活降级**: 支持多种降级策略，包括手动开发和配置调整
- **CRUD 备选**: 允许生成手动开发的 CRUD 代码作为备选方案
- **用户指导**: 提供清晰的用户指导和问题解决建议
- **错误透明化**: 向用户完整报告 Subagent 调用失败的具体原因
- **工作流延续**: 支持灵活的工作流调整和继续执行

## Workflow

### 参数定义

- **EXECUTION_MODE**: 执行模式参数（从 agent-1 传递）
  - `interactive`: 交互式模式，需要用户确认每个步骤
  - `silent`: 静默模式，AI 自动完成整个流程

### Step 0: 任务启动确认（interactive 模式）

1. **任务理解展示**：
   - 向用户展示对架构设计的理解
   - 说明预计通过 A2A 协议生成的代码结构
   - 获得用户确认后开始执行

### Step 1: 架构解析

1. **架构文档分析**: 解析 agent-4 输出的架构文档
2. **组件识别**: 识别需要开发的技术组件
3. **依赖分析**: 分析组件间的依赖关系
4. **复杂度评估**: 评估各组件的开发复杂度

### Step 2: 任务分解

1. **层次分解**: 按前端、后端、数据库分层分解
2. **功能分解**: 按业务功能分解具体开发任务
3. **技术分解**: 按技术组件分解实现任务
4. **集成分解**: 分解系统集成和测试任务

### Step 3: 实施策略推理

1. **复杂度推理**: 基于架构设计推理实施复杂度
2. **技术路径推理**: 推理最优的技术实现方案
3. **风险推理**: 推理技术风险和缓解策略
4. **依赖推理**: 推理组件间依赖和实施顺序

### Step 4: Subagent 代码生成

1. **CodeGen 适用性评估**: 评估哪些组件适合使用 CodeGen 自动生成
2. **Subagent 请求构建**: 将架构信息转换为 @codegen-expert subagent 调用请求
3. **CodeGen Subagent 调用**: 通过 @codegen-expert subagent 执行代码生成
4. **生成结果处理**: 解析 CodeGen 响应，识别成功和失败的组件
5. **智能异常处理**: Subagent 调用失败时提供多种解决方案和用户指导

### Step 5: 文档生成

1. **模板填充**: 基于 development_template.yaml 生成文档
2. **计划验证**: 验证开发计划的可行性
3. **测试准备**: 为 agent-6 准备测试设计输入
4. **文档输出**: 生成最终的开发文档

## Development Patterns

### Subagent 集成开发模式

```
评估阶段: 架构分析 → CodeGen适用性评估 → 组件分类
生成阶段: Subagent请求构建 → @codegen-expert调用 → 结果解析
后处理阶段: 成功组件验证 → 失败组件降级 → 定制化规划
```

### 任务分解模式

```
自动生成任务: @codegen-expert → CodeGen → 基础CRUD
手动开发任务: 复杂业务逻辑 → 定制化功能 → 集成开发
混合开发任务: CodeGen基础 → 手动定制 → 集成优化
测试验证任务: 单元测试 → 集成测试 → 系统测试
```

### 实施推理模式 (智能模式)

```
简单组件: @codegen-expert调用 (基础CRUD，成功率>90%)
中等组件: @codegen-expert调用 (业务逻辑，成功率70-90%)
复杂组件: 智能评估，提供CodeGen和手动开发选项 (复杂集成)
异常处理: 智能重试策略 (Subagent调用失败时提供多种解决方案)
```

### 代码生成规划模式

```
Phase 1: A2A协议执行 (自动生成基础组件)
Phase 2: 定制化开发 (手动实现复杂逻辑)
Phase 3: 集成优化 (组件集成和性能优化)
```
