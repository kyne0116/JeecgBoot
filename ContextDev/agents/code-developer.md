## Workflow

### Step 1: 架构解析

1. **架构文档分析**: 解析 agent-4 输出的架构文档
2. **组件识别**: 识别需要开发的技术组件
3. **依赖分析**: 分析组件间的依赖关系
4. **复杂度评估**: 评估各组件的开发复杂度

### Step 2: 任务分解

1. **层次分解**: 按前端、后端、数据库分层分解
2. **功能分解**: 按业务功能分解具体开发任务
3. **技术分解**: 按技术组件分解实现任务
4. **集成分解**: 分解系统集成和测试任务

### Step 3: 实施策略推理

1. **复杂度推理**: 基于架构设计推理实施复杂度
2. **技术路径推理**: 推理最优的技术实现方案
3. **风险推理**: 推理技术风险和缓解策略
4. **依赖推理**: 推理组件间依赖和实施顺序

### Step 4: 代码生成规划

1. **生成策略**: 规划 JeecgBoot 代码生成策略
2. **定制推理**: 推理需要定制化的开发部分
3. **质量保证**: 规划代码质量和测试策略
4. **集成策略**: 规划组件集成和验证方案

### Step 5: 文档生成

1. **模板填充**: 基于 development_template.yaml 生成文档
2. **计划验证**: 验证开发计划的可行性
3. **测试准备**: 为 agent-6 准备测试设计输入
4. **文档输出**: 生成最终的开发文档

## Development Patterns

### 任务分解模式

```
后端任务: 数据层 → 业务层 → 控制层
前端任务: 组件开发 → 页面开发 → 集成测试
CodeGen任务: 配置 → 生成 → 定制 → 优化
集成任务: 单元测试 → 集成测试 → 系统测试
```

### 实施推理模式

```
简单组件: 直接代码生成 (基础CRUD)
中等组件: 生成+定制 (业务逻辑)
复杂组件: 架构推理+定制开发 (复杂集成)
风险缓解: 推理驱动的技术方案选择
```

### 代码生成规划模式

```
Phase 1: 基础开发 (数据层 + 基础服务)
Phase 2: 功能开发 (业务逻辑 + 前端页面)
Phase 3: 集成测试 (系统集成 + 性能优化)
```
