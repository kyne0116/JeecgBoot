# JeecgBoot 测试计划文档模板 v3.0 - EARS 风格

## 模板说明

本模板采用 **EARS (Easy Approach to Requirements Syntax)** 风格，用自然语言描述测试计划，专注于"如何测试"而非技术细节。

### EARS 测试语法
```
GIVEN [测试前提] 
WHEN [测试场景]
THEN [预期结果]
WHERE [测试约束]
```

## 🔍 功能测试

### 如何验证功能正确性？

#### 用户登录测试

**GIVEN** 系统已启动且用户账号存在  
**WHEN** 用户输入正确的用户名和密码  
**THEN** 用户能够成功登录系统  
**WHERE** 登录后显示用户信息和功能菜单

**GIVEN** 系统已启动  
**WHEN** 用户输入错误的用户名或密码  
**THEN** 系统显示登录失败提示  
**WHERE** 不允许用户进入系统

#### 数据管理测试

**GIVEN** 用户已登录且有相应权限  
**WHEN** 用户创建新的数据记录  
**THEN** 数据能够成功保存到数据库  
**WHERE** 数据格式正确且通过验证规则

**GIVEN** 用户已登录且有相应权限  
**WHEN** 用户查询数据列表  
**THEN** 系统显示符合条件的数据  
**WHERE** 数据按指定规则排序和分页

**GIVEN** 用户已登录且有相应权限  
**WHEN** 用户修改现有数据  
**THEN** 数据更新成功并记录操作日志  
**WHERE** 修改后的数据通过业务规则验证

**GIVEN** 用户已登录且有相应权限  
**WHEN** 用户删除数据记录  
**THEN** 数据被标记为删除状态  
**WHERE** 删除操作可以被审计追踪

#### 权限控制测试

**GIVEN** 用户具有特定角色权限  
**WHEN** 用户尝试访问功能菜单  
**THEN** 只显示用户有权限的功能  
**WHERE** 无权限的功能不可见或不可操作

**GIVEN** 用户没有某项操作权限  
**WHEN** 用户尝试执行该操作  
**THEN** 系统拒绝操作并显示权限不足提示  
**WHERE** 不泄露敏感信息

## ⚡ 性能测试

### 如何验证系统性能？

#### 响应时间测试

**GIVEN** 系统在正常负载下运行  
**WHEN** 用户执行常规操作  
**THEN** 系统在规定时间内响应  
**WHERE** 页面加载不超过3秒，查询不超过1秒

#### 并发用户测试

**GIVEN** 多个用户同时使用系统  
**WHEN** 并发用户数达到预期峰值  
**THEN** 系统仍能正常提供服务  
**WHERE** 响应时间不显著增加，无功能异常

#### 数据量测试

**GIVEN** 数据库中有大量测试数据  
**WHEN** 用户查询或处理大量数据  
**THEN** 系统性能保持在可接受范围  
**WHERE** 使用分页和优化查询策略

## 🔒 安全测试

### 如何验证系统安全性？

#### 身份认证测试

**GIVEN** 用户未登录系统  
**WHEN** 用户尝试直接访问内部页面  
**THEN** 系统重定向到登录页面  
**WHERE** 所有受保护资源都需要认证

#### 权限验证测试

**GIVEN** 用户已登录但权限不足  
**WHEN** 用户尝试访问受限功能  
**THEN** 系统拒绝访问并记录尝试  
**WHERE** 不暴露系统内部信息

#### 数据安全测试

**GIVEN** 用户输入包含恶意代码  
**WHEN** 系统处理用户输入  
**THEN** 恶意代码被过滤或转义  
**WHERE** 防止SQL注入和XSS攻击

## 💡 使用说明

### 如何使用这个测试模板？

1. **明确测试目标**: 基于需求和设计文档确定测试重点
2. **确定测试范围**: 明确需要测试的功能和模块
3. **设计测试用例**: 使用EARS格式编写具体测试用例
4. **准备测试环境**: 搭建接近生产环境的测试环境
5. **准备测试数据**: 创建覆盖各种场景的测试数据
6. **执行测试**: 按计划执行各类测试
7. **验收确认**: 确认测试结果满足质量要求

### EARS测试格式提示

- **GIVEN**: 描述测试前提条件，测试开始前的状态
- **WHEN**: 描述测试操作，用户或系统执行的动作
- **THEN**: 描述预期结果，系统应该产生的响应
- **WHERE**: 描述测试约束，特殊条件或限制

### 常见问题

**Q: 测试用例应该多详细？**  
A: 详细程度要适中，既要覆盖测试场景，又要便于执行

**Q: 如何确保测试覆盖率？**  
A: 基于需求和设计文档，确保每个功能点都有对应的测试用例

**Q: 测试发现问题如何处理？**  
A: 及时记录问题，跟踪修复进度，验证修复效果

**注意**: 本文档采用EARS风格，专注于测试计划描述。具体测试执行和工具使用请参考对应的技术文档。
