# JeecgBoot 需求规格文档模板 v3.0 - EARS 风格

## 模板说明

本模板采用 **EARS (Easy Approach to Requirements Syntax)** 风格，使用自然语言描述业务需求，专注于"做什么"而非"怎么做"。

### EARS 语法结构

```
GIVEN [前置条件]
WHEN [触发事件]
THEN [期望结果]
WHERE [约束条件]
```

## 💡 使用说明

### 如何使用这个模板？

1. **填写基本信息**: 完成项目基本信息部分
2. **明确业务目标**: 用简单语言描述要解决的问题
3. **定义用户角色**: 列出所有会使用系统的人员
4. **编写功能需求**: 使用 EARS 格式描述每个功能
5. **补充非功能需求**: 描述性能、安全等要求
6. **确定验收标准**: 明确如何验证需求已满足

### EARS 格式提示

- **GIVEN**: 描述前置条件，什么情况下这个需求适用
- **WHEN**: 描述触发事件，什么动作会引发这个需求
- **THEN**: 描述期望结果，系统应该做什么
- **WHERE**: 描述约束条件，有什么限制或特殊要求

### 常见问题

**Q: 如何区分功能需求和非功能需求？**
A: 功能需求描述系统"做什么"，非功能需求描述系统"如何做"（性能、安全等）

**Q: EARS 格式是否适用于所有需求？**
A: 大部分需求都适用，对于复杂的业务流程可以分解为多个 EARS 语句

**Q: 如何确保需求的完整性？**
A: 使用验收标准部分，确保每个需求都有对应的验证方法

**注意**: 本文档采用 EARS 风格，专注于业务需求描述。技术实现细节请参考对应的设计文档和 AI 编程规范。
