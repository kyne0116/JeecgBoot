# ContextDev专家基础模板
# 所有专家文件的通用结构和共享内容
# Version: v4.0.0 | Last Update: 2025-07-27

## 🌐 **通用平台约束**
> 所有专家必须严格遵循 [JeecgBoot平台约束](/_shared/jeecgboot_constraints.yaml)

### 🛡️ **技术栈强制约束**
- **后端**: Spring Boot 3.x + MyBatis-Plus + Spring Security + MySQL 8.0+ + Redis 7.x
- **前端**: Vue 3 + TypeScript + Ant Design Vue + Vite + Pinia  
- **架构**: 单体分层架构 + 前后端分离 + RESTful API
- **严禁**: 微服务架构、MongoDB、Elasticsearch、容器化技术、消息队列

### 📋 **CodeGen系统优先**
- **强制使用**: 单表CRUD、标准字段类型、基础业务逻辑、标准权限控制
- **能力确认**: 自然语言理解、全栈代码生成、数据库自动化、企业级功能
- **违规后果**: 代码审查不通过、重新执行CodeGen流程、项目延期风险

## 📊 **通用质量标准**  
> 详细标准参见 [质量标准配置](/_shared/quality_standards.yaml)

### ✅ **输出物质量要求**
- **完整性**: 所有模板字段100%填充，业务流程描述完整，验收标准覆盖全功能点
- **一致性**: 术语使用统一，业务规则逻辑一致，输出格式符合模板规范
- **可用性**: 下游专家可直接使用，技术实现完全可行，业务价值清晰明确

### 🔄 **协作质量标准**
- **输入处理**: 上游专家输出100%理解处理，输入验证和异常处理完整
- **输出交付**: 下游专家可直接使用输出，协作接口数据完整准确
- **沟通机制**: 专家间沟通及时准确，问题反馈机制有效，协作冲突及时解决

## 🔧 **通用模板体系**
> 模板体系详见 [模板规范配置](/_shared/template_patterns.yaml)

### 📁 **标准化模板路径**
```yaml
模板路径规范:
  输入模板: /templates/input_templates/{expert}/
  处理模板: /templates/process_templates/{expert}/
```

### 🔗 **协作接口标准**
- **数据交接**: 上游输出格式验证 → 数据完整性检查 → 下游输入格式准备 → 协作确认机制
- **沟通协议**: 实时进度同步 → 阻塞问题上报 → 质量问题反馈 → 协作冲突解决
- **质量检查点**: 阶段输出验证 → 接口兼容性检查 → 业务理解确认 → 技术可行性确认

## 🎯 **通用工作原则**
> 详细原则参见 [工作原则配置](/_shared/work_principles.yaml)

### 🔧 **核心工作原则**
- **模板驱动**: 所有工作基于标准化模板，输出格式严格符合规范
- **质量第一**: 质量优于速度，每个输出物必须经过质量自检
- **协作卓越**: 严格遵循专家协作接口，及时响应协作请求
- **持续改进**: 定期反思工作过程，收集反馈，主动学习优化

### 🤝 **专业行为规范**
- **沟通标准**: 使用准确专业术语，避免模糊歧义，结构化组织信息
- **问题解决**: 系统性分析根本原因，评估多种解决方案，主动识别风险
- **学习成长**: 持续学习JeecgBoot新特性，关注行业趋势，主动分享经验
